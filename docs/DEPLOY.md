# Deploying the demo

Production topology: ARCHITECTURE.md §8. Everything here uses free plans.

| Part | Service | Defined by |
|---|---|---|
| API | Render web service, Singapore, Free | `render.yaml` |
| Database | Neon Postgres, Singapore | this page |
| Till and back office | Cloudflare Pages | this page and `apps/pos/public/_headers` |
| Backups | GitHub Actions → Cloudflare R2 | `.github/workflows/backup.yml`, [RESTORE.md](RESTORE.md) |

**Secrets** go only into the service's own dashboard or a git-ignored `.env*` file. Never commit
them or paste them into a chat, issue or pull request.

## 1. Code on `main`

- [ ] Commit, open a pull request, wait for CI to pass, merge. Render and Pages build from `main`,
      and Render deploys only after CI passes.

## 2. Neon (database)

- [ ] Create a project: region **AWS Asia Pacific (Singapore)**, Postgres **17**.
- [ ] Under **Connect**, copy two connection strings for the same database:
  - with **Connection pooling on** (the host contains `-pooler`): this is `DATABASE_URL`;
  - with it **off**: this is `DIRECT_URL`.

## 3. Render (API)

- [ ] **New → Blueprint**, connect the repository. Render reads `render.yaml`.
- [ ] Enter the values it asks for:

  | Variable | Value |
  |---|---|
  | `DATABASE_URL` | Neon pooled connection string |
  | `DIRECT_URL` | Neon direct connection string |
  | `CORS_ORIGINS` | the address the till will have, such as `https://apparel-pos.pages.dev`, **no trailing slash** (corrected in step 5) |

  `ADMIN_JWT_SECRET` is generated by Render. Variables added to `render.yaml` later with
  `sync: false` are **not** asked for again: add them under **Environment**.
- [ ] Wait for the deploy. The log should say the migrations were applied, then
      `Nest application successfully started`.
- [ ] Note the service address and open `<API>/v1/health`. It answers `{"status":"ok"}`.

If the build fails on the pnpm version, set the environment variable `PNPM_VERSION=10.34.9` and
deploy again.

## 4. Cloudflare Pages (till)

- [ ] **Workers & Pages → Create → Pages → Connect to Git**, choose the repository.
- [ ] Settings:

  | Setting | Value |
  |---|---|
  | Production branch | `main` |
  | Framework preset | None |
  | Root directory | leave empty (the repository root) |
  | Build command | `pnpm turbo run build --filter=pos...` |
  | Build output directory | `apps/pos/dist` |

- [ ] Environment variables (Production):

  | Variable | Value |
  |---|---|
  | `VITE_API_URL` | the Render address, without `/v1` |
  | `NODE_VERSION` | `24` |
  | `PNPM_VERSION` | `10.34.9` |

- [ ] Deploy and note the address. `VITE_API_URL` is built into the app: after changing it, deploy
      again.

## 5. Allow the till to call the API

- [ ] In Render → **Environment**, set `CORS_ORIGINS` to the exact Pages address and save. Pages
      preview addresses are not allowed.

## 6. Seed the demo data

Run once from your machine. It only adds what is missing, so running it again is safe.

- [ ] Create `apps/api/.env.production.local` with one line, `DIRECT_URL=` followed by the Neon
      direct connection string.
- [ ] Check that `git status` does **not** list the file.
- [ ] ```bash
      pnpm install
      pnpm --filter api db:seed:prod
      ```
      It prints the database host, then `Seed complete: 15 products, 120 variants.` Check that the
      host is Neon's, not `127.0.0.1`.

It creates store `S01`, terminals `T1` and `T2` with the demo codes, the demo staff and PINs, the
catalogue, and one **Linen Shirt, Black / M**. To use other enrolment codes, add
`SEED_ENROL_CODE_T1` and `SEED_ENROL_CODE_T2` to the file **before** the first run.

## 7. Check the live system

A Free service that has been idle takes about a minute to answer its first request.

- [ ] Headers (`<POS>` is the Pages address):
      ```bash
      curl -sI <POS>/ | grep -i cache-control                 # no-cache
      curl -sI <POS>/sw.js | grep -i cache-control            # no-cache
      curl -sI <POS>/manifest.webmanifest | grep -i cache     # no-cache
      curl -s  <POS>/ | grep -o '/assets/[^"]*\.js'           # then:
      curl -sI <POS>/assets/<that file> | grep -i cache       # max-age=31536000, immutable
      curl -sI <POS>/receipt/test | grep -iE '^HTTP|content-type'   # 200, text/html
      ```
- [ ] Enrol: open `<POS>` in two separate browser profiles and set up one with `DEMO-S01-T1` and the
      other with `DEMO-S01-T2`. Clear one profile's site data and enrol the same code again.
- [ ] Offline sale: log in (`1111`), reload once, then DevTools → Network → Offline. Sell an item;
      the badge shows 1 unsynced receipt. Go online; it turns to "All synced".
- [ ] Deep link: on a receipt screen, reload. The receipt is shown after logging in.
- [ ] Proxy count, which decides whose address the rate limits count:
      ```bash
      for i in 1 2 3 4; do
        curl -si <API>/v1/sync/pull -H "X-Forwarded-For: 203.0.113.$i" | grep -i x-ratelimit-remaining
      done
      ```
      (`401` is expected.) The number must **fall by one each time**. Then run it once from another
      network, such as a phone hotspot: it should start near 119, not carry on.
  - Stays near 119 every time: `TRUST_PROXY_HOPS` is too high and clients can fake their address.
    Lower it.
  - Jumps about, or the second network carries on the same count: the API is counting a proxy.
    Raise it by 1, redeploy and check again.

## 8. Backups

- [ ] Make a key pair, outside the repository:
      ```bash
      age-keygen -o pos-backup.key      # prints the public key, age1...
      ```
      Store the key file in a password manager and keep a second copy offline.
- [ ] Cloudflare → **R2** → create a bucket, for example `pos-backups` (keep it private).
- [ ] Bucket → **Settings → Object lifecycle rules**: delete objects with prefix `daily/` after
      **30** days, and with prefix `monthly/` after **365** days.
- [ ] R2 → **Manage API tokens** → create a token with **Object Read & Write**, limited to that
      bucket. Note the access key id, the secret access key and your account id.
- [ ] GitHub → repository **Settings → Secrets and variables → Actions → New repository secret**:

  | Secret | Value |
  |---|---|
  | `BACKUP_DATABASE_URL` | Neon **direct** connection string |
  | `AGE_PUBLIC_KEY` | the `age1...` line, not the key file |
  | `R2_ACCOUNT_ID` | your Cloudflare account id |
  | `R2_ACCESS_KEY_ID` | from the token |
  | `R2_SECRET_ACCESS_KEY` | from the token |
  | `R2_BUCKET` | the bucket name |

  Without all four `R2_*` secrets, backups are kept as workflow artifacts for 30 days instead.
- [ ] **Actions → Backup → Run workflow** on `main`. Check that the file is in the bucket's `daily/`
      folder (or attached to the run).
- [ ] Do the restore drill in [RESTORE.md](RESTORE.md) once, with that file.

## 9. Uptime monitor

- [ ] [UptimeRobot](https://uptimerobot.com) → **Add monitor**: type HTTP(s), URL
      `<API>/v1/health`, interval 5 minutes, alert to your email.

The health check never queries the database, so Neon can still sleep. The monitor does keep the Free
Render service awake, which fits within its 750 free hours a month for one service.

## Optional: a database role without schema rights

ARCHITECTURE.md §11 asks for the API to connect without the right to change the schema. In Neon's
SQL editor, with a strong password of your own:

```sql
CREATE ROLE pos_app LOGIN PASSWORD '<choose one>';
GRANT USAGE ON SCHEMA public TO pos_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO pos_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO pos_app;
```

Then use `pos_app` and its password in the **pooled** `DATABASE_URL`. `DIRECT_URL` keeps the owner,
because migrations need it. Run step 6 first or afterwards; both work.
